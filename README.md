# Spectroscopy LMM

Code and data to reproduce the results in:  

*Transfer and uncertainty for soil spectroscopy: a parsimonious approach using Bayesian mixed models and soil surveys*<br/>
E Potash, C Partida, J Safanelli, E Forbes, A Polussa, T Runge, M Sheffer, J Sanderman<br/>
European Journal of Soil Science (2026)

## Overview

Data processing and model cross validation is executed in an R [targets](https://books.ropensci.org/targets/) pipeline and then results are loaded into a quarto notebook where they are visualized.
Specifically this repository contains:

```sh
.
├── data/                 # raw datasets
│   ├── hudson_lab.csv    # soil carbon outcomes
│   ├── hudson_NIR.csv    # spectroscopy predictors
│   ├── hudson_sites.csv  # site-level metadata
│   └── hudson_soils.csv  # sample-level metadata
├── R/                    # helper scripts
├── figures/              # manuscript figures
│   ├── figures.html      # rendered document
│   └── figures.qmd       # source document
├── README.md             # this file
└── _targets.R            # targets pipeline definition
```

## Reproducing the results

### 1. Install required R packages:

```r
install.packages(c(
  "tidyverse",
  "cmdstanr",
  "brms",
  "mdatools",
  "tidybayes",
  "resemble",
  "tidymodels",
))
```

### 2. Execute pipeline

```{r}
targets::tar_make()
```

Note that by default this will build one target at a time but the most computationally intensive targets, namely the Bayesian LMM fits, are sampled with four parallel chains.
On my older Intel laptop each LMM fit takes about 15 minutes and this pipeline fits 24 of them so it will take 6+ hours.
(It should be much faster on a newer Mac. See also notes on computation below.)

### 3. Generate figures

Open the results notebook `md/results.md` and either execute each cell interactively or render the document to HTML.

## Notes

### Code

The codebase was originally designed to experiment on multiple datasets, multiple outcomes, data transformations, etc.
As a result it is (much) more complicated than strictly necessary for reproducing the analysis in the manuscript. Apologies!

### Computation

The Stan model generated by `brms` is not optimal. It takes 5 minutes just to compile! (But a one-time 5 min compilation isn't that big of a deal here given each fit takes 15 minutes and we do 24 fits per model.)
I suspect that writing a more vectorized version directly in Stan would both compile and sample much faster. If you are interested in using this model please contact me for advice.
